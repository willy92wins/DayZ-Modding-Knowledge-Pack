# LF_UIProbe

Source-only, first-party, Dabs-free probe to pin B19/B20 in DayZDiag.

## Preparation

The repository normalizes text to LF. That is why CRLF variant is not versioned
as assumption: it is generated byte-by-byte in a new directory.

```powershell
python tools/dayz-ui-lab/probe/prepare_probe.py `
  --out reports/dayz-ui-lab/probe/LF_UIProbe
```

The preparer fails if destination already exists. The result contains:

- `leaf-without-child-block.layout`;
- `continuation-lf.layout`;
- `continuation-crlf.layout`;
- a vanilla-first client mod loading all three fixtures once.

## Evidencia requerida

Execute via authorized DayZ MCP lifecycle or manually with
DayZDiag. Keep the RPT span between:

- `[LF_UI_PROBE_BEGIN]`
- `[LF_UI_PROBE_END]`

The `LF_UI_PROBE_RESULT` logs report the text returned by
`ButtonWidget.GetText(out string)`. There is no hardcoded expected value:
B20 can only be pinned after observing both LF/CRLF cases in engine.
Do not use offline parser as substitute for that observation.
